# 存款保障对账台（deposit-cover）

按「同一存款人 + 同一法人机构」把存款合并成组、每组按限额封顶，算出有多少在保障之内、
敞口集中在哪一家、还要几家机构才装得下，并给出可一键采用的分散方案。

- 体验地址：https://xululu0401.github.io/deposit-cover/
- 纯前端单文件应用：`index.html` = `template.html` + `core.js` + `ui.js`（由 `build.cjs` 拼装）
- 不联网、不上传、不查任何机构的真实情况；限额与金额全部由用户填写

## 算法要点

1. 按「持有人 + 机构名归一化后」合并存款类，同一机构的多笔算一组
2. 每组本息合计 = Σ(本金 + 利息)；受保 = min(本息合计, 限额)；敞口 = 超出部分
3. 存款类覆盖率 = 受保合计 ÷ 存款类合计；全口径覆盖率 = 受保合计 ÷（存款类 + 非存款类）
4. 某持有人「最少机构数」= 该人存款类合计 ÷ 限额，向上取整（金额可自由拆分时的下界）
5. 参考分散方案：把超限组的超出部分先填给同一持有人还有额度的组，再新开机构——贪心的一种可行解
6. 金额一律用整数「分」计算，不经浮点小数

## 边界（页面内同样写明）

不做汇率与外币存款；不处理联名账户与共有存款的归属争议；不查机构法人名录（同名即同机构）；
不处理企业存款、大额存单转让；不算利息税；**不预测任何机构的经营状况、不做安全性评价、
不给「该不该取出来」的建议**；不联网、不判断某个产品是否受保。默认样例与内置场景均为虚构示例。
